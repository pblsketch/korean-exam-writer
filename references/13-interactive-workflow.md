# 13 · 대화형 휴먼인더루프(HITL) 워크플로

한 번의 요청으로 완성본을 뱉지 않는다. 아래 **체크포인트**마다 오케스트레이터가 산출물을 제시하고
**교사의 응답을 기다린다(멈춤)**. 각 체크포인트는 [제시] → [질문] → [교사 승인/수정] 구조다.
교사가 "빠르게/알아서"를 원하면 체크포인트를 묶되, **출처 확인·지문 검토·문항 검토 3개는 생략하지 않는다**
(환각·오류 방지의 핵심 지점이라 최소 이 셋은 사람 눈을 거친다).

## 체크포인트 1 · 교실 맥락 수집  ⏸ 대기
- **질문**: `09-classroom-context.md`의 필수 항목 중 빠진 것을 2~4개씩 묶어 묻는다.
- **완료 조건**: 학년·영역·목적·난이도·문항수·소스모드·출력형식 확정.

## 체크포인트 2 · 글감·주제 선택  ⏸ 대기
- **제시**: (자료조사관) 맥락에 맞는 **주제 후보 3개**(각 한 줄 설명 + 왜 이 학년·난이도에 적합한지).
  - 소스 A/B면 교사 원문·자료를 받아 주제를 확인. C면 후보 제시.
- **질문**: "어느 주제로 갈까요? 직접 지정도 됩니다."
- **완료 조건**: 주제 1개 확정.

## 체크포인트 3 · 원본 출처 확인  ⏸ 대기  (생략 불가)
- **제시**: (자료조사관) 확보한 **출처 목록**(제목·출처·핵심 근거 스니펫·신뢰도 평가). C모드는 검색 근거,
  A/B모드는 교사 자료의 어느 부분을 근거로 쓸지.
- **질문**: "이 출처·근거를 사용해도 될까요? 신뢰가 어려운 항목은 빼겠습니다."
- **완료 조건**: 사용할 근거 확정. **검증 불가한 근거는 교사 확인 없이 쓰지 않는다.**

## 체크포인트 4 · 지문 개요 검토  ⏸ 대기
- **제시**: (설계자) **개요(blueprint)** — 주/보조 전개 방식, 문단별 기능(6~8), 핵심 개념·관계,
  밑줄 표지 계획(㉠~㉤), 예상 문항 유형 배분.
- **질문**: "이 구성으로 쓸까요? 강조할 개념·전개 방식·빼고 싶은 부분 있으면 알려주세요."
- **완료 조건**: 개요 승인(수정 요청 시 반영 후 재제시).

## 체크포인트 5 · 지문 초안 검토  ⏸ 대기  (생략 불가)
- **선행**: (집필가) 개요대로 집필 → (사실 검증관) 적대적 사실 검증 통과 → 교사에게 제시.
- **제시**: 완성 지문 + **검증 요약**(무엇을 근거로 썼는지, 제거·수정한 사실, 저신뢰 표시).
- **질문**: "사실·난이도·표현을 검토해 주세요. 고칠 부분이 있나요?"
- **완료 조건**: 지문 승인(수정 시 집필가→검증관 루프 후 재제시).

## 체크포인트 6 · 문항 검토  ⏸ 대기  (생략 불가)
- **선행**: (출제가) 유형 배분·인지 계약·오답 레시피로 출제 → (문항 검토관) 품질 검증 →
  `validate_exam.py` 기계 게이트 통과 → 교사에게 제시.
- **제시**: 문항+정답+간단 해설, 유형 배분표, 각 오답이 왜 틀린지, 검증 리포트.
- **질문**: "난이도·정답·오답이 의도대로인가요? 특정 문항만 다시 낼까요?"
- **완료 조건**: 문항 승인(수정 시 해당 문항만 재생성 후 재게이트).

## 체크포인트 7 · 조판·출력
- (조립관) 승인된 exam → HTML(→PDF) / HWPX. 교사용 정답·검증 리포트·"최종 검토 필요" 고지 포함.
- **완료 후**: 무엇을 검증했고 무엇을 제거·수정했는지 요약 보고.

## 진행 규칙
- **⏸ 대기 지점에서는 다음 단계로 넘어가지 않는다.** 교사 응답을 받고 진행한다.
- 각 제시는 **간결하게**(요점 + 선택지). 장문 나열 금지.
- 교사가 앞 단계를 뒤집으면(예: 주제 변경) 영향받는 이후 산출물을 다시 만든다.
- **빠른 모드**: 교사가 원하면 CP1·2·4를 묶어 기본값으로 빠르게 통과하되, CP3·5·6(출처·지문·문항 검토)은 유지.
